# requirements.md - 선박 의약품 재고 관리 시스템 요구사항

무엇을 만들지와 무엇이 맞는 동작인지를 정의한다. 어떻게 만들지는 `design.md`, 왜 그렇게 정했는지는 `decisions.md`.

## 1. MVP 범위

- 포함: 로그인과 역할(관리자·의무사관), 계정 관리, 선박·약품·비치 기준 관리, 재고 입고, 약품 사용(FEFO 차감, 동시성 제어, 멱등성), 사용 취소, 재고 현황 조회, 배포
- 이후 단계: 사용 정정, 로트 폐기, 사용 이력 조회, 화면, JWT 전환, 만료 배치, 목록 커서 전환

## 2. 역할과 권한

### 1. 역할별 권한

| 기능                     | 관리자        | 의무사관               |
|--------------------------|---------------|------------------------|
| 계정 등록·목록           | O             |                        |
| 약품 카탈로그 등록       | O             |                        |
| 선박 등록                | O             |                        |
| 비치 기준 설정           | O             |                        |
| 입고                     |               | O (소속 선박)          |
| 사용 기록                |               | O (소속 선박)          |
| 사용 취소                |               | O (본인이 기록한 것만) |
| 약품·선박 조회           | O             | O                      |
| 비치 기준 조회           | O (모든 선박) | O (소속 선박)          |
| 재고 현황 조회           | O (모든 선박) | O (소속 선박)          |

### 2. 권한 규칙

- 로그인하지 않은 요청: 401.
- 역할에 없는 기능: 403.
- 의무사관이 소속이 아닌 선박의 `shipId`로 요청: 403.
- 의무사관이 남이 기록한 사용을 취소: 403.
- 판정 순서와 세부 규칙은 `design.md` 2.2.

## 3. 재고 판정 규칙

- 약품별 가용 재고: 해당 배·해당 약품의 로트 중 `status='ACTIVE' AND expiry_date >= 오늘(UTC) AND remaining_quantity > 0`인 것들의 합.
- 부족 여부: 가용 재고 < `min_quantity`.
- 만료 여부: `expiry_date < 오늘(UTC)`. 저장하지 않고 조회 시 판정.
- 유효기한 임박: 가용 로트 중 `expiry_date`가 임박 기준(30일) 이내 인 것.

## 4. Edge Case

- 입력 검증:
    - 수량 0/음수 → 400,
    - 없는 약품 및 선박 → 404,
    - 음수 최소 수량 → 400,
    - 입고 시각 누락 또는 현재(UTC)보다 미래 → 400. 과거 시각은 제한 없음.
    - 입력 길이가 컬럼 길이(`design.md` 1.3)를 초과 → 400.
- 계정 등록:
    - 비밀번호 8자 미만 또는 72바이트 초과 → 400,
    - 의무사관인데 `shipId` 없음, 관리자인데 `shipId` 있음 → 400,
    - 로그인 ID 중복 → 409.
- 비치 기준 설정:
    - 신규 201, 수정 200,
    - 같은 선박·약품의 동시 신규 요청 → 둘 다 성공(201과 200). 행은 1개이고 마지막에 처리된 값이 남음.
- 목록 조회:
    - `page`는 0~21474836, 생략 시 0. `size`는 1~100, 생략 시 20. 정렬은 `id` 오름차순,
    - 범위를 벗어나거나 숫자가 아닌 `page`, `size` → 400,
    - 범위 안에서 마지막 페이지 뒤의 `page` → 200, 빈 `content`.
- 재고 경계:
    - 가용 0/부족 → 409+가용 수량 메시지,
    - 잔량 합 = 요청량 → 정상,
    - 유효기한 오늘 로트 → 당일까지 유효,
    - 전 로트 만료 → 가용 0,
    - 유효기한 동일 로트 → `received_at` 다음 `id`순.
- 인증, 인가:
    - 로그인 안 함 → 401,
    - 역할에 없는 기능 → 403,
    - 의무사관의 다른 선박 요청 → 403,
    - 남이 기록한 사용 취소 → 403.

## 5. 테스트 시나리오

- 기준 시각: 테스트는 고정 `Clock`을 주입하며 오늘 = 2026-07-22(UTC). 시나리오의 날짜는 모두 이 기준이다.

- FEFO 차감
    - Given: 로트A(잔량 100, 만료 2027-01), 로트B(잔량 30, 만료 2026-08).
    - When: 아스피린 40정 사용.
    - Then: 201. 로트B에서 30 차감(잔량 0), 로트A에서 10 차감(잔량 90). allocations = [{B,30},{A,10}].
- 재고 부족
    - Given: 가용 재고 총 3.
    - When: 5정 사용.
    - Then: 409(requested:5, available:3). 어떤 로트도 차감되지 않고 사용기록도 생성되지 않는다.
- 동시성
    - Given: 로트A 잔량 10. 같은 배 소속 의무사관 officer_1, officer_2.
    - When: officer_1이 7정, officer_2가 5정을 거의 동시에 사용.
    - Then: 먼저 잠근 쪽이 201, 다른 하나는 409. 최종 잔량은 3(7정 성공) 또는 5(5정 성공). 두 요청이 모두 성공하는 일은 없다.
- 멱등성
    - Given: key=K로 40정 사용 성공(잔량 100→60).
    - When: 같은 사용자가 같은 key=K로 재요청.
    - Then: 200. 동일 usageId 반환. 추가 차감 없이 잔량 60 유지.
- 멱등 키 재사용
    - Given: key=K로 40정 사용 성공.
    - When: 같은 사용자가 key=K로 30정 사용 요청.
    - Then: 409(IDEMPOTENCY_KEY_REUSED). 차감 없음.
- 같은 키 동시 요청
    - Given: 로트A 잔량 100.
    - When: 같은 사용자가 key=K, 40정 요청을 거의 동시에 두 번 보냄.
    - Then: 하나는 201, 다른 하나는 200(같은 usageId). 최종 잔량 60. 사용기록 1건.
- 로트 번호 중복 입고
    - Given: 선박 1, 아스피린에 lotNumber "L-001" 존재.
    - When: 같은 선박·약품으로 "L-001" 입고.
    - Then: 409(DUPLICATE_LOT).
- 취소 복원
    - Given: 사용#100 = 로트B 30 + 로트A 10(로트B 잔량 0, 로트A 잔량 90). 기록자 officer_1.
    - When: officer_1이 사용#100 취소.
    - Then: 200, status CANCELLED. 로트B 0→30, 로트A 90→100. 사용기록은 삭제하지 않고 분배내역도 보존.
- 이중 취소
    - Given: 사용#100이 이미 취소됨.
    - When: officer_1이 사용#100 재취소.
    - Then: 200(기존 취소 결과 반환). 추가 복원 없음.
- 유효기한 경계
    - Given: 오늘 07-22. 로트X(잔량 50, 만료 07-22), 로트Y(잔량 50, 만료 07-21).
    - When: 60정 사용.
    - Then: 로트X만 가용(50), 60 > 50이므로 409. 로트Y(만료)는 제외.
- 기준 없는 약품
    - Given: 모르핀은 카탈로그에 있고 비치 기준은 없으며 로트 5앰플 존재.
    - When: (a) 3앰플 사용, (b) 재고 현황 조회.
    - Then: (a) 201, 잔량 2. (b) 현황에 available:2, requirementSet:false, minQuantity:null, shortage:null로 표시.
- 과거 유효기한 입고
    - Given: 오늘 07-22.
    - When/Then: 만료 07-20 입고 → 400. 만료 07-22 입고 → 201.
- 입고 시각 입력
    - Given: 현재 2026-07-22T00:00:00Z.
    - When/Then: (a) receivedAt 03-01T09:00Z → 201, received_at = 03-01T09:00Z.
                 (b) receivedAt 07-23T00:00Z → 400(RECEIVED_AT_IN_FUTURE).
                 (c) receivedAt 누락 → 400.
- 입고자 기록
    - When: officer_1이 로트를 입고.
    - Then: 201. 해당 로트의 received_by = officer_1의 id.
- FEFO 동점
    - Given: 로트P(잔량 20, 만료 08-01, 입고 03-01), 로트Q(잔량 20, 만료 08-01, 입고 05-01).
    - When: 10정 사용.
    - Then: received_at이 빠른 로트P부터 차감. 실행할 때마다 결과 동일.
- 재고 0 부족 경고
    - Given: 모르핀 비치 기준 5, 로트 0개.
    - When: 재고 현황 조회.
    - Then: available:0, minQuantity:5, shortage:true. 재고가 0인데도 경고가 뜬다.
- 취소분 재사용
    - Given: 로트A 잔량 0 (전량 차감된 상태).
    - When: (a) 취소, (b) 이어서 50정 사용.
    - Then: (a) 로트A 0→100. (b) 201, 복원분에서 50 차감(잔량 50).
- 입력 검증
    - 수량 0/음수 → 400, 없는 medicationId → 404, 최소 수량 음수 → 400, 없는 usageId 취소 → 404.
- 계정 입력 규칙
    - When/Then: (a) 비밀번호 7자 → 400. 8자 → 201.
                 (b) 비밀번호 72바이트 → 201. 73바이트 → 400.
                 (c) loginId 31자 → 400.
                 (d) 의무사관인데 shipId 없음, 관리자인데 shipId 있음 → 400.
- 로그인 ID 중복
    - Given: loginId "officer_1" 계정 존재.
    - When: 관리자가 같은 loginId로 계정 등록.
    - Then: 409(DUPLICATE_LOGIN_ID). 계정이 추가되지 않는다.
- 비치 기준 설정
    - When/Then: (a) 기준이 없는 선박·약품에 설정 → 201.
                 (b) 같은 선박·약품에 다시 설정 → 200, 최소 수량 변경, 행 1개.
                 (c) 기준이 없는 선박·약품에 거의 동시에 두 번 설정 → 하나는 201, 다른 하나는 200. 행 1개.
- 목록 페이지네이션
    - Given: 선박 25척.
    - When/Then: (a) 파라미터 없음 → 200, content 20개, totalElements:25, totalPages:2, hasNext:true.
                 (b) page=1 → 200, content 5개, hasNext:false.
                 (c) page=2 → 200, 빈 content.
                 (d) page=-1, page=21474837, size=0, size=101, page=abc → 400.
- 미로그인
    - When: 세션 없이 재고 현황 조회.
    - Then: 401.
- 역할 위반
    - When: (a) 관리자가 사용 기록, (b) 의무사관이 약품 등록.
    - Then: 둘 다 403. 아무것도 저장되지 않는다.
- 다른 선박 접근
    - Given: officer_1은 선박 1 소속.
    - When: officer_1이 선박 2에 입고 또는 사용.
    - Then: 403. 선박 2의 재고는 변하지 않는다.
    - 존재하지 않는 선박 999로 요청해도 403(404 아님).
    - officer_1이 선박 2의 비치 기준 또는 재고 현황을 조회해도 403.
- 남의 기록 취소
    - Given: 사용#100의 기록자는 officer_1.
    - When: 같은 배의 officer_2가 사용#100 취소.
    - Then: 403. 로트 잔량과 사용기록 상태는 변하지 않는다.
