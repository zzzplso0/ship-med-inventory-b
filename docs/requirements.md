# requirements.md - 선박 의약품 재고 관리 시스템 요구사항

무엇을 만들지와 무엇이 맞는 동작인지를 정의한다. 어떻게 만들지는 `design.md`, 왜 그렇게 정했는지는 `decisions.md`.

## 1. MVP 범위

- 포함: 로그인과 역할(관리자·의무사관), 계정 관리, 선박·약품·비치 기준 관리, 재고 입고, 약품 사용(FEFO 차감, 동시성 제어, 멱등성), 사용 취소, 재고 현황 조회, 배포
- MVP 다음 단계: 화면(6장), 로트 목록·폐기, 사용 이력 조회
- 이후 단계: JWT 전환, 만료 배치, 목록 커서 전환
- 사용 정정은 별도 기능으로 두지 않는다. 잘못 기록한 사용은 취소한 뒤 다시 기록한다.

### 2. 권한 규칙

- 로그인하지 않은 요청: 401.
- 역할에 없는 기능: 403.
- 의무사관이 소속이 아닌 선박의 `shipId`로 요청: 403.
- 의무사관이 남이 기록한 사용을 취소: 403.
- 판정 순서와 세부 규칙은 `design.md` 2.2.

## 3. 재고 판정 규칙

- 약품별 가용 재고: 해당 배·해당 약품의 로트 중 `status='ACTIVE' AND expiry_date >= 오늘(UTC) AND remaining_quantity > 0`인 것들의 합.
- 부족 여부: 가용 재고 < `min_quantity`. `min_quantity`가 0이면 항상 부족 아님(`shortage:false`).
- 만료 여부: `expiry_date < 오늘(UTC)`. 저장하지 않고 조회 시 판정.
- 유효기한 임박: 가용 로트 중 `expiry_date <= 오늘(UTC) + 30일`인 것(양 끝 포함). 오늘이 07-22이면 07-22 ~ 08-21.

## 4. Edge Case

- 입력 검증:
    - 수량 0/음수 → 400,
    - 없는 약품 및 선박 → 404,
    - 음수 최소 수량 → 400,
    - 입고 시각 누락 또는 현재(UTC)보다 미래 → 400. 과거 시각은 제한 없음.
    - 입력 길이가 컬럼 길이(`design.md` 1.3)를 초과 → 400.
    - 약품 `category`는 생략할 수 있지만, 빈 문자열이거나 공백만 있으면 → 400.
    - 사용 취소·로트 폐기 `reason` 누락, 빈 문자열, 공백만 있음 → 400.
- 계정 등록:
    - 비밀번호는 8~20자, 영문·숫자·특수문자(`@$!%*#?&`)를 각각 1자 이상 포함. 영문은 대소문자를 구분하지 않고, 그 외 문자는 허용하지 않음. 위반 → 400,
    - 의무사관인데 `shipId` 없음, 관리자인데 `shipId` 있음 → 400,
    - 로그인 ID 중복 → 409.
- 비치 기준 설정:
    - 신규 201, 수정 200,
    - 같은 선박·약품의 신규 요청이 겹치면 → 하나는 201, 다른 하나는 409. 행은 1개이고 먼저 저장된 값이 남음. 409를 받은 요청은 다시 보내면 수정되어 200.
- 목록 조회:
    - `page`는 0~21474836, 생략 시 0. `size`는 1~100, 생략 시 20. 정렬은 `id` 오름차순(로트 목록·사용 이력은 아래 각 항목),
    - 범위를 벗어나거나 숫자가 아닌 `page`, `size` → 400,
    - 범위 안에서 마지막 페이지 뒤의 `page` → 200, 빈 `content`.
- 재고 경계:
    - 가용 0/부족 → 409+가용 수량 메시지,
    - 잔량 합 = 요청량 → 정상,
    - 유효기한 오늘 로트 → 당일까지 유효,
    - 전 로트 만료 → 가용 0,
    - 유효기한 동일 로트 → `received_at` 다음 `id`순.
- 사용 기록 멱등성:
    - 같은 `Idempotency-Key`로 없는 약품 요청 → 404. 키 재사용(409)보다 먼저 판정.
    - 취소된 기록의 `Idempotency-Key`로 같은 내용 재요청 → 200, 현재 상태(`status:CANCELLED`) 반환. 다시 차감하지 않음.
- 로트 목록:
    - 필터: 약품(`medicationId`), 상태(`ACTIVE`, `DISCARDED`). 생략하면 전체.
    - 정렬: FEFO(`expiry_date → received_at → id`).
    - 만료 여부는 3장 규칙으로 조회 시점에 계산해 표시. 폐기·잔량 0 로트도 목록에 나온다.
    - 잘못된 상태 값 → 400. 없는 약품으로 거르면 → 200, 빈 `content`.
- 로트 폐기:
    - 경로의 선박에 없는 로트(다른 선박의 로트 포함) → 404.
    - 이미 폐기된 로트 → 200, 기존 폐기 결과. 사유·폐기자는 바뀌지 않는다.
    - 잔량 0인 로트도 폐기할 수 있다.
    - 폐기한 로트는 가용 재고와 사용 차감에서 빠진다. 잔량은 그대로 남는다.
    - 폐기한 로트가 걸린 사용을 취소하면 그 로트로 그대로 복원한다. 복원분은 가용 재고에 들어가지 않는다.
- 사용 이력:
    - 필터: 기간(`from`, `to`. UTC 날짜, 양 끝 포함, `used_at` 기준), 약품(`medicationId`), 상태(`ACTIVE`, `CANCELLED`). 생략하면 전체.
    - 정렬: `used_at` 내림차순, 같으면 `id` 내림차순.
    - 취소된 기록도 나오며, 취소 시각·취소자·사유와 로트별 차감 내역을 함께 보여 준다.
    - `from`이 `to`보다 늦음, 잘못된 날짜·상태 값 → 400. 없는 약품으로 거르면 → 200, 빈 `content`.
- 인증, 인가:
    - 로그인 안 함 → 401,
    - 역할에 없는 기능 → 403,
    - 의무사관의 다른 선박 요청 → 403,
    - 남이 기록한 사용 취소 → 403,
    - 관리자가 로트 폐기 → 403.

## 5. 테스트 시나리오

- 기준 시각: 테스트는 고정 `Clock`을 주입하며 오늘 = 2026-07-22(UTC). 시나리오의 날짜는 모두 이 기준이다.

- FEFO 차감
    - Given: 로트A(잔량 100, 만료 2027-01), 로트B(잔량 30, 만료 2026-08).
    - When: 아스피린 40정 사용.
    - Then: 201. 로트B에서 30 차감(잔량 0), 로트A에서 10 차감(잔량 90). allocations = [{B,30},{A,10}].
- 재고 부족
    - Given: 가용 재고 총 3.
    - When: 5정 사용.
    - Then: 409(requested:5, available:3). 어떤 로트도 차감되지 않고 사용기록도 생성되지 않는다.
- 동시성
    - Given: 로트A 잔량 10. 같은 배 소속 의무사관 officer_1, officer_2.
    - When: officer_1이 7정, officer_2가 5정을 거의 동시에 사용.
    - Then: 먼저 잠근 쪽이 201, 다른 하나는 409. 최종 잔량은 3(7정 성공) 또는 5(5정 성공). 두 요청이 모두 성공하는 일은 없다.
- 멱등성
    - Given: key=K로 40정 사용 성공(잔량 100→60).
    - When: 같은 사용자가 같은 key=K로 재요청.
    - Then: 200. 동일 usageId 반환. 추가 차감 없이 잔량 60 유지.
- 멱등 키 재사용
    - Given: key=K로 40정 사용 성공.
    - When: 같은 사용자가 key=K로 30정 사용 요청.
    - Then: 409(IDEMPOTENCY_KEY_REUSED). 차감 없음.
- 같은 키 동시 요청
    - Given: 로트A 잔량 100.
    - When: 같은 사용자가 key=K, 40정 요청을 거의 동시에 두 번 보냄.
    - Then: 하나는 201, 다른 하나는 200(같은 usageId). 최종 잔량 60. 사용기록 1건.
- 로트 번호 중복 입고
    - Given: 선박 1, 아스피린에 lotNumber "L-001" 존재.
    - When: 같은 선박·약품으로 "L-001" 입고.
    - Then: 409(DUPLICATE_LOT).
- 취소 복원
    - Given: 사용#100 = 로트B 30 + 로트A 10(로트B 잔량 0, 로트A 잔량 90). 기록자 officer_1.
    - When: officer_1이 사용#100 취소.
    - Then: 200, status CANCELLED. 로트B 0→30, 로트A 90→100. 사용기록은 삭제하지 않고 분배내역도 보존.
- 이중 취소
    - Given: 사용#100이 이미 취소됨.
    - When: officer_1이 사용#100 재취소.
    - Then: 200(기존 취소 결과 반환). 추가 복원 없음.
- 유효기한 경계
    - Given: 오늘 07-22. 로트X(잔량 50, 만료 07-22), 로트Y(잔량 50, 만료 07-21).
    - When: 60정 사용.
    - Then: 로트X만 가용(50), 60 > 50이므로 409. 로트Y(만료)는 제외.
- 기준 없는 약품
    - Given: 모르핀은 카탈로그에 있고 비치 기준은 없으며 로트 5앰플 존재.
    - When: (a) 3앰플 사용, (b) 재고 현황 조회.
    - Then: (a) 201, 잔량 2. (b) 현황에 available:2, requirementSet:false, minQuantity:null, shortage:null로 표시.
- 과거 유효기한 입고
    - Given: 오늘 07-22.
    - When/Then: 만료 07-20 입고 → 400. 만료 07-22 입고 → 201.
- 입고 시각 입력
    - Given: 현재 2026-07-22T00:00:00Z.
    - When/Then: (a) receivedAt 03-01T09:00Z → 201, received_at = 03-01T09:00Z.
                 (b) receivedAt 07-23T00:00Z → 400(RECEIVED_AT_IN_FUTURE).
                 (c) receivedAt 누락 → 400.
- 입고자 기록
    - When: officer_1이 로트를 입고.
    - Then: 201. 해당 로트의 received_by = officer_1의 id.
- FEFO 동점
    - Given: 로트P(잔량 20, 만료 08-01, 입고 03-01), 로트Q(잔량 20, 만료 08-01, 입고 05-01).
    - When: 10정 사용.
    - Then: received_at이 빠른 로트P부터 차감. 실행할 때마다 결과 동일.
- 재고 0 부족 경고
    - Given: 모르핀 비치 기준 5, 로트 0개.
    - When: 재고 현황 조회.
    - Then: available:0, minQuantity:5, shortage:true. 재고가 0인데도 경고가 뜬다.
- 유효기한 임박
    - Given: 로트W(만료 07-21), 로트X(만료 07-22), 로트Y(만료 08-21), 로트Z(만료 08-22). 모두 잔량 10.
    - When: 재고 현황 조회.
    - Then: available:30, expiringSoon = [X, Y]. W는 만료라 제외, Z는 임박 기준 밖.
- 취소분 재사용
    - Given: 로트A 잔량 0 (전량 차감된 상태).
    - When: (a) 취소, (b) 이어서 50정 사용.
    - Then: (a) 로트A 0→100. (b) 201, 복원분에서 50 차감(잔량 50).
- 입력 검증
    - 수량 0/음수 → 400, 없는 medicationId → 404, 최소 수량 음수 → 400, 없는 usageId 취소 → 404.
- 계정 입력 규칙
    - When/Then: (a) 비밀번호 7자 → 400. 8자 → 201.
                 (b) 비밀번호 20자 → 201. 21자 → 400.
                 (c) 영문이 대문자뿐인 비밀번호 → 201. 영문, 숫자, 특수문자 중 하나가 없음 → 400. 허용하지 않는 문자 포함 → 400.
                 (d) loginId 31자 → 400.
                 (e) 의무사관인데 shipId 없음, 관리자인데 shipId 있음 → 400.
- 로그인 ID 중복
    - Given: loginId "officer_1" 계정 존재.
    - When: 관리자가 같은 loginId로 계정 등록.
    - Then: 409(DUPLICATE_LOGIN_ID). 계정이 추가되지 않는다.
- 비치 기준 설정
    - When/Then: (a) 기준이 없는 선박·약품에 설정 → 201.
                 (b) 같은 선박·약품에 다시 설정 → 200, 최소 수량 변경, 행 1개.
                 (c) 기준이 없는 선박·약품에 신규 설정 요청이 겹침 → 하나는 201, 다른 하나는 409(REQUIREMENT_CONFLICT). 행 1개.
- 목록 페이지네이션
    - Given: 선박 25척.
    - When/Then: (a) 파라미터 없음 → 200, content 20개, totalElements:25, totalPages:2, hasNext:true.
                 (b) page=1 → 200, content 5개, hasNext:false.
                 (c) page=2 → 200, 빈 content.
                 (d) page=-1, page=21474837, size=0, size=101, page=abc → 400.
- 미로그인
    - When: 세션 없이 재고 현황 조회.
    - Then: 401.
- 역할 위반
    - When: (a) 관리자가 사용 기록, (b) 의무사관이 약품 등록.
    - Then: 둘 다 403. 아무것도 저장되지 않는다.
- 다른 선박 접근
    - Given: officer_1은 선박 1 소속.
    - When: officer_1이 선박 2에 입고 또는 사용.
    - Then: 403. 선박 2의 재고는 변하지 않는다.
    - 존재하지 않는 선박 999로 요청해도 403(404 아님).
    - officer_1이 선박 2의 비치 기준 또는 재고 현황을 조회해도 403.
- 남의 기록 취소
    - Given: 사용#100의 기록자는 officer_1.
    - When: 같은 배의 officer_2가 사용#100 취소.
    - Then: 403. 로트 잔량과 사용기록 상태는 변하지 않는다.
- 로트 폐기
    - Given: 아스피린 로트A(잔량 100, 만료 2027-01), 로트B(잔량 30, 만료 2026-08).
    - When: (a) officer_1이 사유를 적어 로트B 폐기, (b) 재고 현황 조회, (c) 40정 사용.
    - Then: (a) 200, status DISCARDED, 폐기 시각·폐기자·사유 기록. 로트B 잔량 30 유지. (b) available:100, 로트B는 expiringSoon에서 빠짐. (c) 로트A에서만 40 차감.
- 재폐기
    - Given: 로트B가 이미 폐기됨.
    - When: officer_1이 다른 사유로 로트B 폐기.
    - Then: 200, 기존 폐기 결과(처음 사유·폐기자) 반환.
- 폐기 입력·권한
    - When/Then: (a) 사유 누락·빈 문자열·공백만 → 400.
                 (b) 관리자가 폐기 → 403.
                 (c) officer_1이 선박 1 경로로 선박 2의 로트 폐기 → 404. 선박 2 경로로 요청하면 403.
                 (d) 잔량 0인 로트 폐기 → 200.
- 폐기 로트 취소 복원
    - Given: 사용#100 = 로트B 30 + 로트A 10. 이후 로트B 폐기.
    - When: officer_1이 사용#100 취소.
    - Then: 200. 로트B 0→30, 로트A 90→100. 가용 재고는 100(로트B 제외).
- 로트 목록
    - Given: 선박 1에 아스피린 로트W(만료 07-21), 로트X(만료 08-01, 폐기), 로트Y(만료 08-01, 입고 X보다 늦음), 모르핀 로트Z(만료 2027-01).
    - When/Then: (a) 필터 없음 → W, X, Y, Z를 FEFO 순으로. W는 만료로 표시.
                 (b) medicationId=아스피린, status=ACTIVE → W, Y.
                 (c) status=abc → 400.
                 (d) 관리자가 선박 1 조회 → 200. officer_1이 선박 2 조회 → 403.
- 사용 이력
    - Given: 선박 1에 사용#1(아스피린, 07-01), 사용#2(모르핀, 07-10, 취소됨), 사용#3(아스피린, 07-20). 선박 2에 사용#4.
    - When/Then: (a) 필터 없음 → #3, #2, #1. #2는 취소 시각·취소자·사유 포함, 모든 기록에 로트별 차감 내역 포함. #4는 나오지 않음.
                 (b) from=07-01, to=07-10 → #2, #1.
                 (c) medicationId=아스피린, status=ACTIVE → #3, #1.
                 (d) from=07-10, to=07-01 → 400.
                 (e) 관리자가 선박 1 조회 → 200. officer_1이 선박 2 조회 → 403.

## 6. 화면

- 브라우저에서 현재 API의 기능 전체를 쓸 수 있게 한다. 역할별 권한(2장), 재고 판정 규칙(3장), 입력 규칙(4장)은 API와 같다.

### 1. 화면 목록

| 화면                     | 관리자             | 의무사관                          |
|--------------------------|--------------------|-----------------------------------|
| 로그인, 로그아웃         | O                  | O                                 |
| 계정 등록·목록           | O                  |                                   |
| 선박 등록·목록           | O                  | 목록만                            |
| 약품 등록·목록           | O                  | 목록만                            |
| 비치 기준 설정·목록      | O (모든 선박)      | 목록만 (소속 선박)                |
| 입고                     |                    | O (소속 선박)                     |
| 사용, 사용 결과·취소     |                    | O (소속 선박)                     |
| 재고 현황                | O (선박 선택)      | O (소속 선박)                     |
| 로트 목록·폐기           | 목록만 (선박 선택) | O (소속 선박)                     |
| 사용 이력·취소           | 목록만 (선박 선택) | O (소속 선박, 취소는 본인 기록만) |

- 사용 취소는 사용 직후 결과 화면과 사용 이력 화면에서 한다.
- 로트 폐기는 로트 목록 화면에서 사유를 적어 한다. 폐기 폼은 의무사관에게, 폐기되지 않은 로트에만 보인다.
- 사용 이력 화면은 목록과 선택한 기록의 상세(로트별 차감 내역, 취소 정보)를 함께 보여 준다. 취소 폼은 의무사관 본인이 기록한, 취소되지 않은 기록에만 보인다.
- 관리자는 재고 현황 화면에서 고른 선박의 로트 목록·사용 이력으로 이동한다.
- 로그인하면 관리자는 선박 목록, 의무사관은 소속 선박의 재고 현황으로 이동한다.

### 2. 동작 규칙

- 로그인하지 않고 화면에 접근하면 로그인 화면으로 이동한다. API는 지금처럼 401.
- 역할에 없는 화면, 소속이 아닌 선박의 화면 → 403 오류 화면. 관리자가 없는 선박을 요청 → 404 오류 화면. 화면에 없는 경로는 API와 같은 404 응답(design 6.3).
- 입력 오류(400)와 비즈니스 충돌(409)은 입력 화면에 메시지로 보여 주고 입력값을 유지한다. 재고 부족은 가용 수량을 함께 보여 준다.
    - 입력 화면에서 찾는 대상이 없는 경우(계정 등록의 없는 선박, 비치 기준의 없는 약품)도 404 화면이 아니라 입력 화면에 메시지로 보여 준다.
    - 약품 등록의 분류 칸을 비우면 생략으로 본다(API는 빈 문자열 400).
- 등록·입고·사용·취소·폐기에 성공하면 다른 화면으로 이동하므로, 새로고침해도 다시 제출되지 않는다.
- 사용 폼을 두 번 제출해도 한 번만 차감한다.
- 화면의 POST 요청은 CSRF 토큰이 없으면 403.

### 3. 확인 항목

- 화면은 자동 테스트를 만들지 않고 로컬·배포 환경의 브라우저에서 직접 확인한다(decisions 부차 22번). API는 5장 테스트를 그대로 유지한다.

- 미로그인 화면 접근
    - When: 세션 없이 재고 현황 화면 요청.
    - Then: 로그인 화면으로 redirect. 같은 요청을 API로 보내면 401.
- CSRF
    - When: (a) CSRF 토큰 없이 화면 POST, (b) CSRF 토큰 없이 API POST.
    - Then: (a) 403, 저장되지 않는다. (b) 기존 API 동작 그대로.
- 사용 폼 중복 제출
    - Given: 로트A 잔량 100.
    - When: 같은 사용 폼(40정)을 두 번 제출.
    - Then: 사용기록 1건, 잔량 60. 두 번 모두 같은 결과 화면.
- 입력 오류 표시
    - When: 재고 3인 약품을 5정 사용 제출.
    - Then: 사용 화면에 재고 부족과 가용 수량(3) 메시지. 차감 없음.
- 화면 권한
    - When: (a) 의무사관이 계정 등록 화면 요청, (b) officer_1이 선박 2의 재고 현황 화면 요청.
    - Then: 둘 다 403 오류 화면.
- 로트 폐기 화면
    - When: officer_1이 로트 목록에서 사유를 적어 로트 폐기 후 재고 현황 확인.
    - Then: 로트 목록에 폐기로 표시되고 폐기 폼이 사라진다. 재고 현황 가용 수량에서 빠진다. 사유를 비우면 목록 화면에 메시지.
- 이력 화면 취소
    - When: (a) officer_1이 사용 이력에서 본인 기록을 골라 취소, (b) officer_2의 기록을 고름, (c) 관리자가 이력을 봄.
    - Then: (a) 이력 화면으로 돌아와 취소됨으로 표시, 재고 현황 복원. (b), (c) 취소 폼이 보이지 않는다.
